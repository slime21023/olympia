= Create Your Own Site
:description: Set up a new documentation site with the Olympia theme: workspace, Astro configuration, content collection, page route, and customization.
:category: Getting Started
:order: 2
:badge: GUIDE
:badge-variant: secondary

`@olympia/theme` is not published to npm. To use it, keep it as a workspace package next to your site. You can either start from this repository and replace the content in `apps/docs`, or follow the steps below to add the theme to a new project.

== Requirements

* **Bun** 1.2 or later installs dependencies and runs the scripts.
* **Node.js** 20 or later runs the Astro CLI.
* **Chrome 123 or later** is the supported browser. The CSS uses `light-dark()`, and the scripts use `Promise.withResolvers` and `Map.groupBy`. Only Chrome has been tested. The build target is `chrome123` in `apps/docs/astro.config.mjs`.

== 1. Set Up the Workspace

Create a project with the theme as one workspace package and your site as another:

[source,text]
----
my-docs/
├─ package.json              # workspaces
├─ packages/
│  └─ olympia-theme/         # copy this folder from the Olympia repository
└─ apps/
   └─ site/                  # your Astro site
----

Copy `packages/olympia-theme` from the Olympia repository into `packages/olympia-theme`. You do not need its `node_modules`, `tests`, or `tsconfig.json`.

[source,json,filename="my-docs/package.json"]
----
{
  "name": "my-docs",
  "private": true,
  "workspaces": ["packages/*", "apps/*"],
  "scripts": {
    "dev": "bun --cwd apps/site dev",
    "build": "bun --cwd apps/site build",
    "preview": "bun --cwd apps/site preview"
  }
}
----

[source,json,filename="my-docs/apps/site/package.json"]
----
{
  "name": "my-site",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "astro dev",
    "build": "astro build && bunx pagefind --site dist",
    "preview": "astro preview"
  },
  "dependencies": {
    "@olympia/theme": "workspace:*",
    "astro": "^5.5.0",
    "pagefind": "^1.3.0"
  }
}
----

The `build` script runs Pagefind after Astro to create the search index.

== 2. Configure Astro

[source,javascript,filename="apps/site/astro.config.mjs"]
----
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: 'https://example.com', // your production URL
  output: 'static',
});
----

[source,json,filename="apps/site/tsconfig.json"]
----
{
  "extends": "astro/tsconfigs/strict",
  "include": [".astro/types.d.ts", "**/*"],
  "exclude": ["dist"]
}
----

== 3. Register the Content Collection

[source,typescript,filename="apps/site/src/content.config.ts"]
----
import { defineCollection, z } from 'astro:content';
import { asciidocLoader } from '@olympia/theme/loader';
import { BADGE_VARIANTS, DEFAULT_CATEGORY, DEFAULT_ORDER } from '@olympia/theme';

const docs = defineCollection({
  loader: asciidocLoader({ base: './src/content/docs' }),
  schema: z.object({
    title: z.string(),
    description: z.string().default(''),
    category: z.string().default(DEFAULT_CATEGORY),
    order: z.number().default(DEFAULT_ORDER),
    badge: z.string().optional(),
    badgeVariant: z.enum(BADGE_VARIANTS).optional(),
    httpMethod: z.string().optional(),
    endpoint: z.string().optional(),
    attributes: z.record(z.string(), z.string()).default({}),
    headings: z
      .array(z.object({ depth: z.number(), slug: z.string(), text: z.string() }))
      .default([]),
  }),
});

export const collections = { docs };
----

[IMPORTANT]
====
Keep the `headings` field. The loader fills it and the on-page table of contents reads it; a schema without it renders an empty table of contents.
====

== 4. Add the Page Route

This single route renders every document with the theme layout:

[source,astro,filename="apps/site/src/pages/[...slug].astro"]
----
---
import { getCollection, render } from 'astro:content';
import { buildDocsNavigation, getAdjacentPages } from '@olympia/theme';
import DocsLayout from '@olympia/theme/layouts/DocsLayout.astro';

export async function getStaticPaths() {
  const entries = await getCollection('docs');
  const { navGroups, flatItems } = buildDocsNavigation(entries);

  return entries.map((entry) => {
    const slug = entry.id === 'index' ? undefined : entry.id;
    const { prevPage, nextPage } = getAdjacentPages(flatItems, entry.id);

    return {
      params: { slug },
      props: { entry, navGroups, searchDocs: flatItems, prevPage, nextPage },
    };
  });
}

const { entry, navGroups, searchDocs, prevPage, nextPage } = Astro.props;
const { Content } = await render(entry);
---

<DocsLayout
  title={entry.data.title}
  description={entry.data.description}
  category={entry.data.category}
  badge={entry.data.badge}
  badgeVariant={entry.data.badgeVariant}
  httpMethod={entry.data.httpMethod}
  endpoint={entry.data.endpoint}
  headings={entry.data.headings}
  navGroups={navGroups}
  searchDocs={searchDocs}
  prevPage={prevPage}
  nextPage={nextPage}
  siteTitle="My Docs"
  version="v1.0.0"
>
  <Content />
</DocsLayout>
----

== 5. Write Content and Run

Every `.adoc` file under `src/content/docs/` becomes a page. `index.adoc` is the home page, and `guide/index.adoc` is served at `/guide`. See link:/authoring/asciidoc-syntax[AsciiDoc Syntax & Formatting] for the page attributes and block syntax.

[source,bash]
----
bun install
bun run dev       # development server with hot reload
bun run build     # static site in apps/site/dist, with the search index
bun run preview   # serve the production build
----

[NOTE]
====
Full-text search uses the Pagefind index, which only exists after `bun run build`. In `dev` the command palette falls back to matching titles, descriptions, and categories.
====

== Customization

`Site name and version`:: The `siteTitle` and `version` props of `DocsLayout`.
`GitHub button`:: The `githubUrl` prop of `DocsLayout` sets the repository link in the header. Leave it out to hide the button.
`Sidebar group order`:: Pass your own list as the second argument: `buildDocsNavigation(entries, ['Getting Started', 'Guides', 'API'])`. Listed groups come first in that order; any others follow alphabetically.
`Colors and sizes`:: The design tokens are CSS variables in `packages/olympia-theme/src/styles/tokens.css`, such as `--o-primary`, `--o-surface`, and `--sidebar-width`. Override them in your own stylesheet, or edit the file in your copy of the theme.
`Extra right-rail content`:: `DocsLayout` has a named slot, `rail`.
`Hosting under a sub-path`:: Set Astro's `base` (for example `base: '/docs'`). Sidebar and pagination links, the header logo link, search, relative images, and root-relative links such as `link:/guide/start[Guide]` all get the base path. Write authored links without it.
`Components`:: The pieces are grouped by feature in `packages/olympia-theme/src/components/` (`layout`, `navigation`, `content`, `search`). You own your copy of the theme, so edit them directly.

== Deploy to GitHub Pages

Copy `.github/workflows/deploy.yml` from the Olympia repository, then in your repository open *Settings → Pages* and set *Source* to *GitHub Actions*. A project site is served from `https://<user>.github.io/<repo>/`, so read the site URL and base path from the environment in `astro.config.mjs`:

[source,javascript,filename="apps/site/astro.config.mjs"]
----
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: process.env.SITE_URL ?? 'https://example.com',
  base: process.env.BASE_PATH ?? '/',
  output: 'static',
});
----

The workflow sets `SITE_URL` to `https://<user>.github.io` and `BASE_PATH` to `/<repo>`. Use `base: '/'` for a custom domain. Add a `src/pages/404.astro` that renders `DocsLayout` with `indexable={false}` so unknown URLs get a styled page, and a `public/.nojekyll` file if you deploy from a branch instead of Actions.
